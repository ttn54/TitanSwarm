# Phase 4.1 Update: Interactive Profile & Functional Backend

## Architecture and UI Flow Update
The UI needs to shift from a passive dashboard to an interactive command center where the user defines their context before unleashing the swarm.

### New Tab Structure
1. **🧑 Profile & Ledger (Context Input):**
   - Text Area for Base Resume / Summary
   - Inputs for Name, Email, GitHub, LinkedIn
   - Inputs for Skills and Experience bullets.
   - *Architecture Note:* This replaces the hardcoded `Zen` profile inside the example. This data is stored in Streamlit `session_state` so the PDF Generator has access to it.

2. **📡 Sourcing Engine (Deployment):**
   - Inputs: `Job Role` (e.g., Software Engineer Intern) and `Location`.
   - Action Button: **"Deploy Swarm"**.
   - *Architecture Note:* Triggers the `UniversalScraper`. Ingests the output into the `In-Memory Repository`.

3. **📥 Action Queue (Review & Render):**
   - Lists jobs pulled from the Sourcing Engine.
   - Each job has a button **"Generate ATS Tailored Resume"**.
   - *Architecture Note:* This button wires the job description + The Profile Data (from Tab 1) through the `PDFGenerator`. It then surfaces the newly created PDF file for download.

## Pydantic Model Adjustments
- Need a new `UserProfile` Pydantic model to formalize the data collected in Tab 1 so it seamlessly passes into the Jinja template without key-errors.

## Test Plan
- Update UI Mock tests to ensure state transitions from `Sourcing` -> `Action Queue` persist without wiping the `UserProfile` data.
